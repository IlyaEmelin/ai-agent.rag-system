# PLAN: RAG-ассистент поддержки онлайн-кинотеатра «Фильмоскоп»

Документ описывает пошаговый маршрут разработки проекта от подготовки окружения до финальной диагностики качества. План синхронизирован со спецификацией `spec.md` и должен использоваться как рабочий трекер выполнения.

## Статусы

- `[ ]` — не начато.
- `[~]` — в работе.
- `[x]` — завершено.
- `[!]` — есть блокер или требуется решение.

## Целевые ориентиры проекта

- Итоговый `recall@5 >= 0.85` на запросах, где ответ есть в базе знаний.
- Итоговый `correctness >= 0.90` по всем 66 тестовым запросам.
- На `gap`-запросах система возвращает согласованный отказ и не выдумывает факты.
- Notebook выполняется сверху вниз без ручных изменений между ячейками.
- Все ключевые решения обоснованы числами, примерами или диагностикой ошибок.

## Принятая техническая рамка

- Основной фреймворк: LangChain.
- Vector store: Chroma, только как локальное прототипное хранилище.
- Embedding-модель по умолчанию: `intfloat/multilingual-e5-base`.
- LLM: локальный сервер Qwen3.5 на `http://localhost:8080/`.
- OpenAI-compatible base URL по умолчанию: `http://localhost:8080/v1`.
- Reranker: `BAAI/bge-reranker-v2-m3`, включается при наличии ресурсов.
- Основной формат сдачи: Jupyter Notebook + модульный код в `src/`.
- Формат docstrings для функций: Google style на русском языке.
- Все комментарии, docstrings и описания функций в коде должны быть написаны на русском языке; английские имена переменных, функций, классов, импортов, моделей, API endpoints и технических параметров допускаются.
- `Settings` в `src/config.py` должен быть сгруппирован по тематическим dataclass-блокам: `runtime`, `data`, `llm`, `judge`, `embedding`, `chroma`, `chunking`, `retrieval`, `reranker`, `generation`; плоский перегруженный список параметров и плоские alias-свойства верхнего уровня в одном классе не допускаются.
